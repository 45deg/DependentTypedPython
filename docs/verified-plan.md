# 純粋なプログラムに向けた verified の拡張計画

この文書は未実装機能の実装順と完了条件を定める。現行の受理範囲は
[verifiedの仕様と証明](verified.md)、横断的な残件は[実装状況](../PROGRESS.md)を参照する。
以下の構文・機能は、現状として明記したもの以外は計画である。

## 対象と保証

対象は、局所変数の再代入を許す純粋なプログラムの関数契約と停止性の検証。
heap、参照を介した更新、動的配列、IO/effectは対象外とする。不変の文字列は追加候補に含める。
ここでheapを除くとはプログラムが操作する可変heapを扱わない意味であり、
実行処理系の内部メモリ確保を禁止・検証するという意味ではない。

型注釈を基本I/Fとし、関数のRefinedを事前・事後条件、局所Refinedを各代入で保つ条件として扱う。
複数の変数にまたがるループ不変条件は明示できるようにする。
`using` で利用する補題を指定し、解けないVCは名前とソース位置のあるgoalとして残す。
明示的な `proofs` は補助手段として維持する。

新機能でも証明項を生成し、既存kernelで再検査する。自動証明の失敗と仕様の反証を区別し、
未解決のVCがある関数は検証済みとして公開しない。使用した公理への依存を追跡する。

## 段階1・2の実装状況

式中・同時代入・ループ初期化の契約呼び出し、比較演算子、Boolの短絡演算・not、条件式、+=、assertを追加した。
契約呼び出しは元のソース位置を持つ一時変数への代入へ正規化し、既存の契約証明で検査する。
詳細な受理範囲とgoal名は[現行仕様](verified.md)を参照。

whileのguard内の契約呼び出しは未対応。ループ前の条件分岐は段階3のループ合成で追加した。
追加テストは `crates/deppy-python/tests/verified_expressions.rs` にあり、kernelによる静的検査と
HIRの計算を確認する。新しい構文の生成Python実行は未検証。

## 段階3の実装状況

複数・入れ子・分岐内のwhile、continue、break、ループ内return、Nat境界のfor rangeを、
自動証明および名前付き証明で扱う。各ループにソース順の番号を付け、
通常の反復は `loop_correct`、途中脱出を持つ反復は追加した `run_correct` で証明する。
どちらも既存kernelで検査し、kernelの規則や公理は追加していない。

continueでは保存・減少、breakではその地点からの継続、returnでは関数の事後条件を検査する。
breakにguardがFalseという証拠を渡さない。内側の停止性と終了条件を外側の検証に使い、
連続するループでは終了時の証拠を次の初期化へ渡す。

for rangeの境界はNat。正のNat stepと負の整数リテラルstepを扱い、stepの絶対値が正であることをVCにする。
境界・stepは入口で一度評価する。非公開cursorと反復回数を使うため、本文でtargetを書き換えても反復順を保つ。
空の反復に対応し、targetは入口で初期化済みのNatに限定する。一般のInt境界・動的な負stepは段階4以降とする。

通常の分岐の継続は、変更した状態を引数に取る関数として共有する。
契約・assert等のVCは各経路の証拠で検査し、証明上区別が必要な経路を統合しない。
途中脱出や局所Refined宣言を持つ分岐は個別に合成する。
本文の保存と減少も一度に合成し、同じ経路の呼び出しVCを重複生成しない。
従来の単一whileの `proof=` とgoal名は維持する。

追加テストは `verified_flow.rs` と `verified_control.rs`。受理・拒否、更新の変更、契約の抽象性、
import／reexport、公理依存、明示的証明の優先、goal名・位置、HIRの計算を確認する。
検査予算は変更していない。ネストしたrangeとbreakの大きな証明テストは1,600万stepと16 MiBのスタックを明示して使う。
予算超過は未検証として扱う。生成Pythonの実行と意味保存の証明はこの変更の検証に含めない。
段階4〜7とwhileのguard内の契約呼び出しは未実装。

## 計画開始時の現状と実装上の制約

- プログラムの基底型はNat／Bool。局所代入・平坦な同時代入・if・returnに対応する。
- 算術演算子はNatの `+`／`*`、比較は `<`／`<=` が中心。
- verified関数の契約呼び出しは直接の代入・returnに対応するが、式中・同時代入内・ループ前の初期化では制限がある。
- ループは関数直下の単一while。不変条件と自然数の減少尺度から全正当性のVCを生成する。
- 自動証明は文脈の証拠、Σの分解・構築、反射律、標準補題、`using` の補題を使う限定探索。
  補題の前提を解くための再帰的な補題連鎖は行わない。
- 証明言語には帰納型・構造的再帰があるが、そのすべてをverified本文の値や制御構造として使えるわけではない。

主要な変更箇所は[式・文のlowering](../crates/deppy-python/src/lower/verified.rs)、
[契約合成](../crates/deppy-python/src/lower/verified/contracts.rs)、
[ループ処理](../crates/deppy-python/src/lower/verified/loops.rs)、
[証明探索](../crates/deppy-elab/src/solve/auto.rs)。
現状は分岐ごとに継続を展開するため、分岐とループの拡張に先立ち共有可能な制御フロー表現を設計する。

## 実装順と完了条件

### 1. 契約呼び出しを式の中で使う

`f(g(x))`、`f(x) + 1`、条件式、同時代入、ループ初期化で契約呼び出しを許可する。
式を内部の一時変数と呼び出しへ正規化し、各呼び出し地点で事前条件を検証する。
継続には事後条件を渡し、calleeの実装を展開して契約を迂回しない。

完了条件:

- 左から右の評価順と、同時代入で全右辺を評価してから更新する意味を保つ。
- 同じ式中の複数の呼び出しに、区別可能なgoalと元ソース位置を付ける。
- 事前条件が不足する呼び出しを拒否し、後続の式は契約から得た証拠だけで検証できる。
- import／reexportを経由する契約、公理依存、明示的な証明の優先を維持する。

### 2. 基本的な式・文をそろえる

`==`／`!=`／`>`／`>=`、Boolの `and`／`or`／`not`、条件式、局所変数の `+=`、`assert` を追加する。
最初はNat／Boolに型を限定する。Pythonの一般的なtruthinessやオペランドを返すand/orには広げない。

`assert P` はPを証明するVCを生成し、証明後の継続でPを利用できるようにする。
未証明の命題を仮定として追加する命令にはしない。

完了条件:

- 短絡評価と条件式の選択された分岐だけに、必要な契約VCを生成する。
- 右辺や分岐の検証に、そこへ到達する条件の証拠を渡す。
- 偽のassert、条件と矛盾する証明、不正な型を拒否する。
- 演算子の表面構文と、型注釈内の命題の対応を仕様に記載する。

段階1・2を最初の実装単位とする。構文を追加するたびに、正規化後の意味と診断位置を確認する。

### 3. 制御フローとループを合成する

通常の継続・return・break・continueを区別する内部表現を用意し、
複数・ネストしたwhile、分岐内のwhileを実装する。その後に `for range` と途中脱出を追加する。
ループごとに不変条件・減少尺度・goalの識別子を持たせる。

完了条件:

- 連続するループでは、前のループの終了条件を次のループの初期化へ渡す。
- 内側ループの契約と停止性を使って、外側ループの不変条件保存を検証する。
- continue経路でも不変条件と尺度の減少を確認する。
- break経路に通常の「条件式が偽」という終了条件を与えない。
- ループ内returnでは関数の事後条件を証明する。
- for rangeの境界・step・反復順序を定義し、空の反復も検証する。
- 継続の共有でVCの不要な重複を抑え、検査予算とソース診断を維持する。

### 4. 数値演算を拡張する

減算、商・剰余、符号付き整数を追加する。実装前に次の意味を決める。

- Natの減算を、下界の証拠を要求する演算とするか、ゼロで打ち切る演算とするか。
- 負数を扱うIntの表現とNatとの明示的な変換。
- 商・剰余の符号規則。Python互換を主張する場合は床除算の規則を採用する。

完了条件:

- ゼロ除算、必要な下界、変換条件をVCにし、未証明なら拒否する。
- 正負の境界と商・剰余の関係を検証する。
- 自然数減算をPythonの符号付き整数減算として扱わない。
- 反復減算やEuclidの互除法などを、手書き補題を許して検証できる。

### 5. 純粋な複合値を扱う

tuple、不変record、Option／Sum、field参照、matchをverified本文に導入する。
必要に応じて固定長の値配列を追加する。更新が必要なら新しい値を返す意味とし、
可変参照やaliasによる更新は導入しない。

完了条件:

- 型注釈・契約・ループ状態を複合型に拡張し、Nat／Bool専用の扱いを整理する。
- matchの各分岐でconstructorとfieldの情報を契約検証に使う。
- 固定長配列を追加する場合は、添字の範囲をFinまたはVCで保証する。
- 証明言語・stdlibの既存型を共有し、同じ役割の別型を増やさない。

### 6. verified関数の再帰と停止性を拡張する

まず自己再帰を、宣言した契約と減少尺度で検証する。
再帰呼び出しでは事前条件と尺度の厳密減少を確認したうえで事後条件を使う。
辞書式尺度を追加し、複数の自然数を使うループと再帰に対応する。
相互再帰と一般の整礎関係はその後の段階とする。

完了条件:

- 減少しない自己呼び出しを拒否し、契約の循環的な自己正当化を防ぐ。
- 辞書式尺度で、先行成分が減少する場合と同値で後続成分が減少する場合を区別する。
- 再帰版と反復版の関数が同じ仕様を満たす例を検証する。
- 停止性の証明と、実行処理系のスタック・メモリ上限を区別して報告する。

### 7. 必要に応じて文字列を追加する

不変文字列の長さ・連結・等価比較を先に追加し、添字と部分文字列を続ける。
コードポイント・バイト・書記素のどれを要素とするか、負の添字とsliceの境界の意味を先に定義する。
Python strとの互換を主張するなら、その意味に合わせる。

完了条件:

- 空文字列、非ASCII文字、境界の添字・sliceを検証する。
- 添字参照に必要な範囲条件を証明する。
- 連結と長さの法則を検査済み補題として用意する。
- 正規表現、encoding変換、locale依存処理はこの段階の対象に含めない。

## 自動証明と実行保証は別に進める

構文の受理範囲と、自動で解ける命題の範囲を分ける。各段階はまず `using` と明示的な証明で
検証できる状態を完成させる。算術の正規化、線形算術、補題探索の強化は、その後に必要性を見て追加する。
探索を強化しても、生成証明の再検査・探索上限・失敗時のgoalを維持する。
一般の不変条件推論や完全な自動証明は、この計画の完了条件にしない。

現在の保証は定義したHIRの意味論に対する正しさと停止性であり、
元のCPythonソースとの意味保存や生成Pythonの実行保証ではない。
Python実行まで保証する目標には、ソースからHIRへの変換とextractionの意味保存を別途扱う必要がある。

各段階で、受理・拒否テスト、誤った更新や条件への変更による検証失敗、importと公理依存の回帰を確認する。
生成コードを実行した検査は静的検査と区別して記録する。実行結果の比較だけで意味保存の証明とはしない。
現行仕様とPROGRESSの対応範囲は、その段階の実装と検証が完了してから更新する。
